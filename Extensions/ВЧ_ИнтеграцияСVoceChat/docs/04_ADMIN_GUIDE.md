## 1. Требования <a name="1-требования"></a>

| Компонент | Версия / Параметр | Примечание |
|:---|:---|:---|
| **1С:Предприятие** | 8.3.20+ | Рекомендуется 8.5.11+ |
| **Конфигурация** | ЗУП 3.1.34+ | Базовая или КОРП |
| **VoceChat** | Любая версия с Bot API | Доступен по сети из сервера 1С |
| **Права доступа** | Администратор 1С | Для установки расширения |
| **Роль в 1С** | `ВЧ_АдминистраторИнтеграции` | Для настройки параметров и управления журналом |

## 2. Установка <a name="2-установка"></a>

1. Скачайте файл расширения `build/ВЧ_ИнтеграцияСVoceChat_v2.1.0.cfe`.
2. Откройте Конфигуратор основной базы.
3. Перейдите: `Конфигурация` → `Расширения конфигурации` → `Добавить`.
4. Выберите файл `.cfe` и нажмите **Открыть**.
5. Нажмите **F7** для обновления конфигурации базы данных.
6. Закройте Конфигуратор и запустите базу в режиме **1С:Предприятие**.

> 💡 **Важно:** Расширение не изменяет типовые объекты ЗУП. При обновлении конфигурации от вендора конфликтов не возникнет.

## 3. Настройка интеграции <a name="3-настройка-интеграции"></a>

### 3.1. Параметры интеграции
Откройте общую форму настроек: `Сервис` → `Настройки интеграции с VoceChat`.

| Параметр | Пример значения | Описание |
|:---|:---|:---|
| **Использовать интеграцию** | ✅ Вкл | Глобальный выключатель |
| **URL сервера** | `chat.company.ru` | IP или домен (без `http://`) |
| **Порт сервера** | `3001` | Порт VoceChat API |
| **Bot API Key** | `Bot_xxxxxx...` | Ключ бота из админки VoceChat |
| **ID канала** | `1234567890` | Числовой ID канала для уведомлений |
| **Таймаут HTTP** | `30` | Секунд до разрыва соединения |
| **Макс. попыток** | `3` | Количество повторных попыток при ошибке |
| **Ответственный кадровик** | `Иванов И.И.` | Пользователь по умолчанию |

Нажмите **Записать и закрыть**.

### 3.2. Настройка прав <a name="32-настройка-прав"></a>
Расширение использует систему ролей для разграничения доступа к журналу уведомлений.

| Роль | Права | Кто использует |
|:---|:---|:---|
| **`ВЧ_АдминистраторИнтеграции`** | Полный доступ: просмотр всего журнала, удаление записей, изменение настроек | Системный администратор, ведущий разработчик |
| **`ВЧ_ЧтениеИнтеграции`** | Просмотр журнала только с отбором `ОтветственныйКадровик = ТекущийПользователь` | Кадровики, HR-менеджеры |

**Как назначить:**
1. Откройте `Администрирование` → `Настройки пользователей и прав` → `Группы доступа`.
2. Создайте группу `Интеграция с VoceChat`.
3. Внутри создайте профили доступа с соответствующими ролями.
4. Добавьте нужных пользователей.

## 4. Проверка работоспособности <a name="4-проверка-работоспособности"></a>

### 4.1. Тестовая отправка
Для быстрой проверки связи без проведения документов используйте тестовую обработку:
1. Перейдите в раздел `Сервис` → `Отправка сообщений VoceChat`.
2. Заполните параметры подключения.
3. Нажмите **Выполнить тест**.
4. Убедитесь, что в канале VoceChat появилось сообщение "Тест из 1С:Предприятия".

### 4.2. Проверка через журнал
1. Создайте и проведите документ `Прием на работу`.
2. Подождите до **30 секунд** (интервал регламентного задания).
3. Откройте `Сервис` → `Журнал уведомлений`.
4. Статус последней записи должен измениться на **✅ Отправлено**.

## 5. Работа с журналом уведомлений <a name="5-работа-с-журналом-уведомлений"></a>

Журнал уведомлений — это основной инструмент для контроля и управления очередью сообщений.

### 5.1. Структура и фильтрация <a name="51-структура-и-фильтрация"></a>

**Путь:** `Интеграция с мессенджером` → `Сервис` → `Журнал уведомлений`.

В верхней части формы расположены отборы:

| Отбор | Тип | Описание | Значение по умолчанию |
|:---|:---|:---|:---|
| **Период** | Поле периода | Диапазон дат для отбора записей | Текущий месяц (с начала месяца по текущую дату) |
| **Статус** | Выпадающий список | Фильтр по статусу уведомления | Не установлен (показываются все статусы) |
| **Сотрудник** | Поле выбора | Отбор по конкретному сотруднику | Не установлен |
| **Документ** | Поле выбора | Отбор по документу «Прием на работу» | Не установлен |

**Возможные значения статуса:**
- `Ожидает отправки` — уведомление ожидает отправки
- `В обработке` - уведомление отправлено, но еще не доставлено
- `Отправлено` — успешно отправлено и доставлено в VoceChat
- `Ошибка отправки` — произошла ошибка при отправке (см. колонку «Текст ошибки»)

**Контекстный отбор:**

При открытии журнала **из формы документа** «Прием на работу»:
1. Автоматически устанавливается **отбор по документу** (текущий документ)
2. Автоматически устанавливается **период** с начала месяца создания документа по текущую дату

Это позволяет быстро просмотреть все уведомления, связанные с конкретным приемом сотрудника.

### 5.2. Управление очередью <a name="52-управление-очередью"></a>

В таблице записи выделены чекбоксами (колонка `Пометка`).

| Кнопка | Иконка | Действие |
|:---|:---|:---|
| **Сформировать** | 🔄 | Обновляет список записей согласно текущим отборам. Нажмите после изменения параметров фильтрации. |
| **Сбросить отборы** | 📄 | Сбрасывает все установленные фильтры (период, статус, сотрудник, документ) к значениям по умолчанию. |
| **Перейти к документу** | 📄 | Открывает карточку «Прием на работу», которая стала причиной уведомления. Доступна при выделении строки с заполненным документом-основанием. |
| **Повторить отправку** | 🔄 | Сбрасывает статус выбранных записей со статусом «Ошибка» на «Ожидает». Регламентное задание автоматически подхватит их снова для отправки. |
| **Удалить записи** | 🗑️ | Удаляет выбранные записи из истории. **Доступно только администраторам** (роль `ВЧ_АдминистраторИнтеграции`). |
| **Выделить всё** | ☑️ | Быстрая пометка всех видимых записей для массовых операций. |
| **Снять все пометки** | ☐ | Снимает пометку со всех записей в списке. |

**Пример использования:**

1. Установите отбор по периоду (например, текущий месяц)
2. Нажмите **Сформировать**
3. Отберите записи со статусом «Ошибка»
4. Отметьте нужные записи чекбоксами
5. Нажмите **Повторить отправку**

## 6. Заполнение исторических данных <a name="6-заполнение-исторических-данных"></a>

Если интеграция была включена недавно, старые записи (созданные до версии 2.1.0) могут не содержать данных о сотруднике или иметь некорректные ссылки.

**Для исправления:** откройте обработку: `Интеграция с мессенджером` → `Сервис` → `Перезаполнение сотрудника в регистре уведомлений`.

### 6.1. Параметры формы <a name="61-параметры-формы"></a>

Перед запуском процесса необходимо настроить параметры обработки на форме:

| Параметр | Описание | Пример |
|:---|:---|:---|
| **Количество строк для отладки** | Ограничивает обработку заданным числом записей (для тестирования). `0` — обрабатывать все записи. | `10` (проверить работу на первых 10 записях) |
| **Пакетный лимит** | Сколько записей обрабатывается в одной транзакции (в одном пакете). `0` — значение по умолчанию (100). | `2` (если всего 10 записей → 5 пакетов по 2 строки) |
| **Интервал логирования** | Частота записей в журнал регистрации. `1` — логировать каждую запись; `N` — каждую N-ную запись. | `1` (подробный лог) или `10` (каждая 10-я) |

**Порядок действий:**
1. Установите нужные значения в полях (для реального запуска рекомендуется оставить значения по умолчанию).
2. Нажмите кнопку **Заполнить сотрудников в истории**.
3. Дождитесь завершения фоновой операции (информация о статусе отобразится в нижней части формы).

> ⚠️ **Важно:** Для реального запуска рекомендуется оставить **Пакетный лимит** = 100–500 и **Интервал логирования** = 1–10, чтобы не перегружать журнал регистрации при больших объёмах данных.


> ⚠️ **Примечание:** При большом количестве записей (>10 000) выполнение может занять значительное время. Это нормальное поведение — процесс не блокирует интерфейс пользователя.

## 7. Устранение неполадок <a name="7-устранение-неполадок"></a>

| Симптом | Возможная причина | Решение |
|:---|:---|:---|
| **Поля настроек заблокированы** | Интеграция не включена глобально | Включите флаг `ВЧ_ИспользоватьИнтеграцию` |
| **Ошибка 401 Unauthorized** | Неверный `BotAPIKey` | Проверьте ключ в админке VoceChat |
| **Ошибка 404 Not Found** | Неверный `IDКанала` | Уточните ID канала (должно быть число) |
| **Уведомления не уходят, статус «Ожидает»** | Регламентное задание отключено | `Администрирование` → `Регламентные задания` → проверьте «ВЧ_ОбработчикОчередиУведомлений» |
| **В журнале не видно записей коллег** | Нет прав `ВЧ_АдминистраторИнтеграции` | Назначьте роль пользователю (см. раздел 3.2) |
| **В журнале пустое поле «Сотрудник»** | Старые данные (до v2.1.0) | Запустите «Заполнение сотрудника в регистре» (см. раздел 6) |
