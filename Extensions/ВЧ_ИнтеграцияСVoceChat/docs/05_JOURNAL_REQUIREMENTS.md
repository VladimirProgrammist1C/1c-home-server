## 1. Контекст и бизнес-проблема

Кадровая служба не имеет прозрачности в процессе отправки уведомлений новым сотрудникам в корпоративный мессенджер. При сбоях сети или ошибках конфигурации сообщения теряются, а сотрудники не получают welcome-инструкции. Администраторы интеграции вынуждены искать проблемные записи через консоль запросов или журналы регистрации, что увеличивает время реакции на инциденты.

**Цель:** Дать бизнесу инструмент визуального контроля, массового управления и автоматического восстановления истории отправки уведомлений без привлечения разработчиков.

## 2. Требования к функционалу (User Stories)

### 👤 Для кадровика
- **Видеть статус:** «Я хочу открыть журнал и сразу понять, кому ушло уведомление, а где ошибка».
- **Фильтровать данные:** «Мне нужно быстро найти уведомления по конкретному сотруднику или документу за нужный период».
- **Переходить к документу:** «Хочу из журнала одним кликом открыть документ «Прием на работу», чтобы проверить данные».
- **Повторять отправку:** «Если вижу ошибку, хочу нажать кнопку и отправить уведомление заново без ручного вмешательства в базу».

### 🛡 Для администратора интеграции
- **Управлять очередью:** «Нужно массово выбирать записи чекбоксами и выполнять операции (повтор/удаление)».
- **Очищать историю:** «Тестовые и устаревшие записи должны удаляться, чтобы не замедлять систему и не искажать отчёты».
- **Видеть всё:** «Администратор должен иметь доступ ко всем записям системы, независимо от ответственного кадровика».

## 3. Требования к безопасности и разграничению прав (ролевая модель)

| Роль | Видимость данных | Доступные действия |
|:---|:---|:---|
| **Кадровик** | Только записи, где он указан ответственным | Просмотр, фильтры, переход к документу, повторная отправка |
| **Администратор** | Все записи системы | Все действия кадровика + массовое удаление записей |

> 💡 **Принцип:** Кадровик не должен видеть уведомления коллег. Администратор имеет полный контроль для поддержки инфраструктуры.

## 4. Критерии приемки (Business Value)

| № | Критерий | Ожидаемый результат |
|:---|:---|:---|
| **Б-1** | Прозрачность | Кадровик находит статус уведомления за ≤ 10 секунд |
| **Б-2** | Повторная отправка | Уведомление в статусе «Ошибка отправки» повторно отправляется в 2 клика |
| **Б-3** | Актуальность аналитики | Фильтр по сотруднику работает корректно для всех записей в журнале |
| **Б-4** | Безопасность | Кадровик не видит чужие документы; кнопка удаления скрыта |
| **Б-5** | Контекст | При открытии из документа журнал сразу показывает только релевантные записи за период документа |
