## 1. Введение <a name="1-введение"></a>

### 1.1. Назначение
Настоящий документ описывает технические требования к обработке **«ВЧ_ЖурналУведомлений»**, предназначенной для просмотра и управления очередью сообщений интеграции 1С:ЗУП 3.1 ↔ VoceChat.

### 1.2. Область применения
Документ предназначен для:
- **Разработчиков**: при реализации и доработке функционала
- **Тестировщиков**: при составлении сценариев проверки (тест-кейсов)
- **Администраторов**: при настройке прав и обучении пользователей

## 2. Функциональные требования <a name="2-функциональные-требования"></a>

### 2.1. Просмотр очереди
Система должна обеспечивать отображение списка записей из регистра сведений **`ВЧ_ОчередьУведомлений`** в табличном виде.

| ID | Требование | Описание |
|:---|:---|:---|
| **Ф-01** | Табличное представление | Данные должны отображаться в таблице с колонками: «Дата», «Статус», «Документ», «Сотрудник», «Ошибка» |
| **Ф-02** | Сортировка | Список должен быть отсортирован по дате создания записи по убыванию (новые сверху) |
| **Ф-03** | Кнопка перехода к документу | Должна быть кнопка «Перейти к документу», открывающая форму соответствующего документа «Прием на работу» |

### 2.2. Фильтрация данных
Пользователь должен иметь возможность настраивать отображаемый список с помощью отборов.

| ID | Требование | Описание |
|:---|:---|:---|
| **Ф-04** | Период | Возможность выбора диапазона дат (Поле периода). По умолчанию: текущий месяц |
| **Ф-05** | Статус | Отбор по полю «Статус» (Ожидает, Отправлено, Ошибка) |
| **Ф-06** | Документ | Отбор по конкретному документу |
| **Ф-07** | Сотрудник | Отбор по конкретному сотруднику |
| **Ф-08** | Контекстный отбор | При открытии из формы документа «Прием на работу» должен автоматически устанавливаться отбор по этому документу и период месяца документа |

### 2.3. Управление записями
Пользователь должен иметь возможность изменять статус записей.

| ID | Требование | Описание |
|:---|:---|:---|
| **Ф-09** | Повторная отправка | Кнопка «Повторить отправку» должна сбрасывать статус помеченных записей со статусом «Ошибка» на «Ожидает» и обнулять счетчик попыток |
| **Ф-10** | Массовое выделение | Пользователь должен иметь возможность пометить несколько записей чекбоксами. Должны быть доступны команды «Выделить все» и «Снять выделение» |
| **Ф-11** | Удаление | Кнопка «Удалить записи» должна удалять помеченные записи из регистра. **Доступно только роли `ВЧ_АдминистраторИнтеграции`** |

## 3. Требования к интерфейсу <a name="3-требования-к-интерфейсу"></a>

### 3.1. Структура формы
Форма обработки должна состоять из следующих элементов:

| Элемент | Тип | Обязательность | Описание |
|:---|:---|:---|:---|
| `ПериодОтбора` | Поле периода | Да | Фильтр по дате |
| `ОтборСтатус` | Поле списка | Нет | Справочник статусов |
| `ОтборДокумент` | Поле выбора | Нет | Ссылка на документ |
| `ОтборСотрудник` | Поле выбора | Нет | Ссылка на сотрудника |
| `СписокЗаписей` | Таблица значений | Да | Основная таблица данных |
| `СписокЗаписей.Пометка`| Булево | Да | Чекбокс в начале каждой строки |
| **Кнопки** | Командная панель | Да | Сформировать, Сбросить, Повторить, Удалить, Перейти к документу |

## 4. Алгоритмы и логика <a name="4-алгоритмы-и-логика"></a>

### 4.1. Запрос данных (`СформироватьНаСервере`)
Система должна выполнять запрос к регистру сведений `ВЧ_ОчередьУведомлений` с учетом текущих отборов и прав пользователя.

**Требования к запросу:**

1. **Источник данных:** Регистр сведений `ВЧ_ОчередьУведомлений`

2. **Отбираемые поля:**
   - ИДСообщения
   - ДатаСоздания
   - Статус
   - ДокументОснование
   - Сотрудник
   - ТекстОшибки
   - ПопыткиОтправки

3. **Обязательные отборы:**
   - По периоду (`ДатаСоздания МЕЖДУ &Нач И &Кон`)
   - По правам пользователя (если не админ → только свои записи)

4. **Опциональные отборы:**
   - По статусу (если выбран)
   - По документу (если выбран)
   - По сотруднику (если выбран)

5. **Сортировка:** По `ДатаСоздания` убыванию (новые сверху)

6. **Производительность:**
   - Использовать индексы регистра
   - Динамическое формирование условий (не выбирать лишнее)

**Принцип работы отбора:**
1. Если пользователь не является администратором, к запросу автоматически добавляется условие:
   `ОтветственныйКадровик = ТекущийПользователь()`
2. Если пользователь является администратором, отбор по ответственному не применяется

### 4.2. Логика кнопки «Повторить отправку»
При нажатии кнопки для каждой помеченной записи должно выполняться:

1. Проверка роли пользователя (наличие права на чтение/запись)
2. Вызов процедуры `ВЧ_ИнтеграцияСервер.ПовторитьОтправку()`
3. Внутри процедуры:
   - Изменение поля `Статус` → `Ожидает отправки`
   - Изменение поля `ПопыткиОтправки` → `0`
   - Очистка поля `ТекстОшибки`

### 4.3. Логика кнопки «Перейти к документу»
При нажатии кнопки:

1. Считывается ссылка на документ из текущей строки таблицы
2. Вызывается метод `ПоказатьЗначение()` для открытия формы документа
3. Если поле «Документ» пустое, выдается предупреждение пользователю

## 5. Нефункциональные требования <a name="5-нефункциональные-требования"></a>

### 5.1. Безопасность
| ID | Требование |
|:---|:---|
| **НФ-01** | Разграничение прав реализовано на уровне запроса |
| **НФ-02** | Доступ к удалению записей закрыт для всех пользователей, кроме роли `ВЧ_АдминистраторИнтеграции` |
| **НФ-03** | Текст сообщения в регистре хранится в зашифрованном/скрытом виде (ХранилищеЗначения), в журнале не отображается |

### 5.2. Производительность
| ID | Требование |
|:---|:---|
| **НФ-04** | Формирование списка должно занимать не более 2 секунд при наличии до 1000 записей в выбранном периоде. **Примечание:** Проверить с помощью тестовой обработки генерации 1000 записей |
| **НФ-05** | Запрос должен использовать индексы регистра (по полям «Дата», «Статус», «Документ») |

## 6. Тестовые сценарии (Test Cases) <a name="6-тестовые-сценарии"></a>

Для приемки функционала должны быть успешно пройдены следующие сценарии:

| № | Сценарий | Ожидаемый результат |
|:---|:---|:---|
| **TC-01** | Открытие формы журнала | Форма открылась, отображается список записей за текущий месяц |
| **TC-02** | Вход под кадровиком | В списке видны только записи, где ответственный = текущий пользователь |
| **TC-03** | Вход под администратором | В списке видны **все** записи. Кнопка «Удалить» активна |
| **TC-04** | Фильтрация по статусу «Ошибка» | В списке остались только записи с красным статусом «Ошибка» |
| **TC-05** | Повторная отправка | После нажатия «Повторить» статус записей изменился на «Ожидает», счетчик попыток стал 0 |
| **TC-06** | Переход к документу | При клике на кнопку открывается форма «Прием на работу» |
| **TC-07** | Удаление записей (не админ) | Кнопка «Удалить» не видна / не активна |
